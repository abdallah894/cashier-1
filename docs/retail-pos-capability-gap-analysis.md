# Retail POS capability gap analysis

**Scope.** Cachier is a bilingual Egypt supermarket POS. This is a product-readiness comparison, not a claim that every feature belongs in the first release. It benchmarks Cachier against documented retail-POS capabilities from Shopify POS, Square for Retail, and Lightspeed Retail. Vendor claims below link only to first-party documentation.

**Repository baseline reviewed (2026-09-30).** Cachier already has authenticated admin/cashier roles, PIN verification with lockout, barcode/manual product lookup, a transactional stock-safe checkout, cash/card payments, per-line and cart discounts, product/category management, manual stock adjustments, receipts/PDF/browser printing, a receipt history, cashier shifts with opening float and closing cash count, and admin sales/profit reports. `create_sale` snapshots product names, unit price, tax, and discounts, and records stock movements atomically. The PWA shell and network indicator exist, but checkout is online-only by design (`docs/offline-plan.md`).

## Priority gaps

| Priority | Missing or incomplete capability | Why it is standard / observed benchmark | Cachier evidence and recommended scope |
| --- | --- | --- | --- |
| P0 | **Returns, refunds, exchanges, and void controls** | Shopify POS supports refunds, restocking, permissions for ineligible/unverified returns, and a return-and-exchange flow; Square Retail presents partial refunds and exchanges as a core capability. [Shopify returns/exchanges](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/order-management/exchange), [Square Retail capabilities](https://squareup.com/us/en/retail/capabilities) | Implemented immutable partial/full returns with mandatory reasons, tender validation, explicit restock/no-restock, manager-PIN threshold approval, return receipts/history, and gross/refund/net reporting. Exchanges persist the return before opening normal checkout for the replacement sale. A void is limited to cancelling an unpaid in-progress cart; historic sales remain immutable. |
| P0 | **Cash-drawer reconciliation beyond sales** | Shopify register sessions include opening/closing float, paid-in/out with reasons, expected-vs-actual discrepancy, payment breakdown, and closed session history. Square documents paid-in/out and drawer event history. [Shopify register sessions](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/cash-register-management/register-sessions-in-shopify-pos), [Square cash drawer reports](https://squareup.com/help/us/en/article/8358-view-cash-drawer-reports) | Cachier records opening float, counted close, expected cash, and cash sales, but has no cash paid-in/out, no variance calculation/reason/approval, no device/till identity, and no complete drawer-event ledger. Add a cash-drawer session plus cash-movement ledger before relying on end-of-shift reconciliation. |
| P0 | **Auditable authority for sensitive operations** | Shopify POS uses unique staff PINs, named roles and manager approvals; its activity log attributes actions such as voids, refunds, manual discounts, and customer access. [Shopify staff management](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/staff-management/understanding-pos-staff-management) Lightspeed separately permissions purchasing, counts/reconciliation, transfers and vendors. [Lightspeed employee roles](https://retail-support.lightspeedhq.com/hc/en-us/articles/229129608-Setting-up-employee-roles-and-access) | Cachier has just `admin` and `cashier`, with PIN lockout. There is no durable actor/action audit log and no granular permission/manager-override model. Add append-only audit events and capability-based permissions as returns, cash movements, discounts, stock corrections, and staff actions are introduced. |
| P0 | **Offline checkout with explicit reconciliation policy** | Shopify supports a defined subset of offline sales and documents restrictions and recovery risks, illustrating that offline behavior must be deliberately bounded—not merely a cached UI. [Shopify offline features](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/selling-offline/offline-features) | Cachier’s own [offline plan](offline-plan.md) says sales still require a network and proposes an IndexedDB outbox, provisional receipts, FIFO sync, and explicit stock-conflict rejection. Implement that design and test disconnection, duplicate submission, stale price/stock, rejected sync, and recovery. |
| P1 | **Stocktakes, discrepancies, and controlled corrections** | Square supports scanner-assisted full/cycle counts, count review/approval and variance; Lightspeed supports full/partial counts plus discrepancy/reconciliation workflows. [Square full inventory counts](https://squareup.com/help/ca/en/article/8249-conduct-full-inventory-counts-with-square-for-retail), [Lightspeed inventory counts](https://retail-support.lightspeedhq.com/hc/en-us/articles/229129948-Performing-inventory-counts-in-Retail-POS) | Cachier has only direct stock adjustments and movement history. Add count sessions (scope, frozen expected quantity, counted quantity, variance, submit/review/approve state), barcode counting, and required reasons for reconciliation. |
| P1 | **Suppliers, purchase orders, receiving, and cost history** | Shopify purchase orders capture supplier, destination, products, costs, taxes, payment terms/status and arrivals; Square Retail documents vendors, POs, bulk receiving, unit costs and alerts. [Shopify purchase orders](https://help.shopify.com/en/manual/products/inventory/purchase-orders/creating-purchase-orders), [Square Retail capabilities](https://squareup.com/us/en/retail/capabilities) | Cachier permits `received` stock movements but has no supplier, PO, receiving workflow, invoice/cost capture, or partial receipt. Add vendors, PO lines, ordered/received/remaining status, cost/tax snapshots, and receiving-generated stock movements. Snapshot unit cost to sale items (or a cost layer) so historic profit does not change after a product-cost edit. |
| P1 | **Multi-location inventory and transfers** | Shopify tracks transfers through in-transit and partial/multiple receipt states. [Shopify inventory transfers](https://help.shopify.com/en/manual/products/inventory/inventory-transfers) | The data model has one `stock_qty` per product and no location/till inventory. If more than one store, warehouse, or branch is planned, introduce locations, per-location stock, transfer orders, in-transit quantities and partial receiving before scaling. Defer this only if Cachier is intentionally single-site. |
| P1 | **Customer accounts, loyalty, gift cards, and rule-based promotions** | Shopify POS customer profiles retain contacts, purchase history, preferences, tax status and marketing consent; discounts can be automatic, coded and combinable; gift cards support issue, redemption, replacement and refund-to-card. [Shopify customer management](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/customer-management), [discount management](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/discount-management), [gift cards](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/payment-management/gift-cards) | Cachier has no customers, loyalty balance, gift-card tender, promotion rules/coupons, or discount authorization. It has manual fixed/percentage line/cart discounts only. Start with customer profiles and receipt linkage, then promotion rules and gift cards only when the operational and accounting rules are specified. |
| P1 | **Payment completeness and lifecycle** | Leading POS products integrate payment lifecycle functions rather than merely recording a tender type; Square lists retail refunds/exchanges and hardware, while Shopify’s offline matrix distinguishes tender capabilities. [Square Retail capabilities](https://squareup.com/us/en/retail/capabilities), [Shopify offline features](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/selling-offline/offline-features) | Cachier records only cash and card at sale creation; card is informational (no terminal/payment reference, authorization/capture/decline/refund lifecycle), and no split tender, mobile wallet, voucher, store credit, or gift-card tender exists. Define the Egypt-supported payment providers and compliance boundary first; then add payment records/references and idempotent status handling. |
| P1 | **Retail hardware and receipt delivery integration** | Shopify supports printing, email/SMS, gift receipts, reprints and customization. Lightspeed supports printer-driven drawer behavior and configurable automatic opening. [Shopify receipt management](https://help.shopify.com/en/manual/sell-in-person/shopify-pos/receipt-management), [Lightspeed cash-drawer setup](https://retail-support.lightspeedhq.com/hc/en-us/articles/228842547-Setting-up-a-cash-drawer) | Cachier supports browser print, PDF download and a camera scanner, but no managed thermal-printer profiles, ESC/POS/drawer integration, USB/Bluetooth scanner setup, email/SMS or gift receipts. Add device configuration/health checks and a supported-hardware matrix; browser printing alone is fragile at a busy till. |
| P2 | **Operational reporting and business-day configuration** | Square cash drawer shifts are per device/location and record events for reconciliation; retail systems also expose inventory movement/adjustment operational detail. [Square Cash Drawers API](https://developer.squareup.com/reference/square/cash-drawers), [Square inventory management](https://squareup.com/help/us/en/article/6110-manage-inventory-with-the-retail-pos-app) | Cachier reports gross sales, product/category/cashier breakdowns and profit, but lacks payment/tender reconciliation, returns/void/discount analysis, tax/VAT report/export, stock valuation/aging, movement/reorder reports, and a store business-day/timezone setting. Current reporting explicitly uses UTC day boundaries; add Cairo business-day configuration and date-close process. |
| P2 | **Reorder operations and inventory quality data** | Square’s retail inventory workflow includes vendors, unit costs, low-stock alerts and adjustment reasons. [Square inventory management](https://squareup.com/help/us/en/article/6110-manage-inventory-with-the-retail-pos-app) | Cachier has low-stock thresholds but no actionable alert/reorder queue, preferred supplier, lead time, pack/case conversion, batch/lot/expiry tracking, or damage/theft/loss reason taxonomy beyond broad adjustments. Prioritize alerts + supplier/reorder links for supermarket operations; add batch/expiry if selling perishables requires traceability. |
| P2 | **Reliability, security operations, and release safeguards** | Not vendor-feature parity, but foundational for a cashier system that must recover predictably at a live till. | The repo has strong transactional checkout invariants, but no visible end-to-end suite/CI observability in the reviewed baseline. Add integration tests for checkout, returns, shifts and offline sync; error monitoring; backup/restore runbook; API rate limits/authentication for the AI route; and incident/support procedures. |

## Recommended delivery order

1. **Financial control:** immutable returns/refunds, cash paid-in/out and drawer variance, audit events/manager approvals.
2. **Inventory accuracy:** stocktake and reconciliation, suppliers/POs/receiving, historic cost snapshot. Add locations/transfers only if expansion requires them.
3. **Counter resilience:** implement the documented offline outbox and add supported printer/drawer/scanner operation.
4. **Customer and growth:** customer profiles, promotional rules, loyalty/gift cards, then payment-terminal integrations.
5. **Scale and operations:** business-day timezone, fuller reports, alerts/reorder, monitoring, CI, recovery procedures.

## Important exclusions

Restaurant-specific workflows (tables, kitchen routing, modifiers and tipping) and e-commerce fulfillment are not baseline requirements for a supermarket cashier. Payroll/timeclock, accounting integrations, fiscal-device/e-invoicing compliance, scales/weighted-barcode standards, and Egypt-specific tax/payment requirements require separate local legal and hardware discovery before implementation.
